Router traffic copy

The NAS is not the gateway. Suricata on the LAN NIC only sees packets to or from this NAS. To inspect LAN ↔ WAN client traffic, the LAN gateway sends a copy toward the NAS. Suricata listens on local tps0. This is IDS only (no packet drop).

OpenWrt uses a GRE tap. MikroTik RouterOS cannot peer with that tap (EoIP is a different GRE flavor), so it streams TZSP instead. Pick the matching option under Capture source.

Note:

  • This package never rewrites the router. You copy the snippets from the NAS and run them on OpenWrt or MikroTik.
  • Do this only on a trusted LAN. Do not allow GRE or TZSP from the WAN.
  • Every WAN byte is copied again toward the NAS. Expect extra LAN load. MikroTik also needs fasttrack off for those flows (CPU cost).
  • Snippets live on the NAS at /var/packages/ThreatPrevention/target/etc/openwrt/ and …/etc/mikrotik/.

What you need

  • OpenWrt (nftables / fw4) or MikroTik RouterOS as the LAN gateway.
  • This NAS on the same LAN, with Threat Prevention installed, setcap applied, and the package started. See This NAS (Suricata IDS).
  • Administrator access to DSM Firewall and SSH on both the NAS and the router.
  • Example addresses used below: router 192.168.1.1, NAS 192.168.1.130. Substitute yours.

Recommended order

  1. Allow GRE (OpenWrt) or UDP 37008 (MikroTik) from the router to this NAS in DSM Firewall.
  2. Install and run the matching router script (OpenWrt shell or MikroTik .rsc).
  3. In Threat Prevention, choose Receive a traffic copy from the router, pick OpenWrt or MikroTik, enter the router LAN IPv4, and click Apply.
  4. Restart this package so tps0 is created.
  5. Confirm capture and alerts.

To allow GRE on this NAS:

  1. Go to Control Panel > Security > Firewall.
  2. Create a rule that allows GRE (IP protocol 47) for OpenWrt, or UDP 37008 for MikroTik, from the router LAN IPv4 (for example 192.168.1.1) to this NAS.
  3. Do not add a generic “allow GRE/TZSP from WAN” or from Any.

Without this rule, tps0 stays quiet even if the tunnel interface exists.

To copy LAN↔WAN traffic on OpenWrt:

  1. From the NAS, copy the folder /var/packages/ThreatPrevention/target/etc/openwrt/ to the router (or copy apply-tps-mirror.sh alone).
  2. On the router, install GRE support if needed: opkg update && opkg install kmod-gre gre.
  3. Run the script with this NAS IPv4:

    NAS_IP=192.168.1.130 sh apply-tps-mirror.sh

  4. Confirm the script printed the WAN L3 device it detected. For PPPoE that must be pppoe-wan (or the equivalent L3 name), not the underlying ethernet. If detection is wrong, rerun with WAN_IF=pppoe-wan NAS_IP=192.168.1.130 sh apply-tps-mirror.sh.

To apply the nft include by hand:

  1. Add the UCI gretap from tps-mirror.network (set ipaddr to the router LAN IP and peeraddr to the NAS). Reload network.
  2. Copy tps-mirror.nft.template to /etc/nftables.d/10-tps-mirror.nft.
  3. Replace __WAN_IF__, __NAS_IP__, and __GRE_DEV__ (often gre-tpsmirror).
  4. Run /etc/init.d/firewall reload.

The nft hook is forward only, so the GRE copy (OUTPUT) is not re-mirrored. The include also returns ip protocol gre.

To copy LAN↔WAN traffic on MikroTik RouterOS:

  1. From the NAS, copy /var/packages/ThreatPrevention/target/etc/mikrotik/ to the router.
  2. Disable or narrow fasttrack-connection. Fasttracked flows never hit mangle, so the NAS stays silent.
  3. Edit NasIp, WanIf, and LanIf in apply-tps-mirror.rsc (PPPoE WAN is often pppoe-out1; LAN is often bridge).
  4. Upload the file and run /import file-name=apply-tps-mirror.rsc.
  5. Confirm with /ip firewall mangle print stats where comment~"tps-mirror".

Do not use EoIP or /interface gre toward this NAS. Those will not appear on tps0.

To enable capture on this NAS:

  1. Open Threat Prevention > Settings > General.
  2. Under Capture source, choose Receive a traffic copy from the router.
  3. Choose OpenWrt — GRE tap or MikroTik — TZSP.
  4. Enter the router LAN IPv4. Leave the optional NAS IP empty unless you must pin a specific address for OpenWrt GRE (empty uses the IPv4 that would be used to reach the router). MikroTik does not need a NAS IP field.
  5. Click Apply.
  6. Restart the package from Package Center, or synopkg restart ThreatPrevention after setcap. The tap is created at package start, not when you click Apply.

Apply writes /var/packages/ThreatPrevention/etc/mirror.conf (enabled=1, encap=gretap or tzsp, ifname=tps0). Creating tps0 needs CAP_NET_ADMIN (the same setcap as capture, or a restart as root via synopkg).

To confirm it is working:

  1. On the NAS: ip link show tps0 — the tap exists and is UP.
  2. cat /var/packages/ThreatPrevention/etc/interface — one line, tps0.
  3. Settings > General > Monitored Interfaces — one enabled device (tps0).
  4. Generate LAN↔WAN traffic (a client browsing the Internet). Events should appear for that client, not only for the NAS itself.
  5. If the tap is up but silent: re-check DSM Firewall (GRE vs UDP 37008), the WAN ifname, forward-only copy, and on MikroTik that fasttrack is off and var/log/tzsp.log is growing.

To disable the traffic copy:

  1. In Settings > General, choose Listen on NAS LAN interfaces and click Apply.
  2. Restart this package. Capture returns to ovs_eth0 (or the LAN pin). tps0 is removed on stop.
  3. On OpenWrt: remove /etc/nftables.d/10-tps-mirror.nft, delete the network.tpsmirror UCI section, then reload network and firewall.
  4. On MikroTik: /ip firewall mangle remove [find comment~"tps-mirror"]. Re-enable fasttrack if you disabled it.
