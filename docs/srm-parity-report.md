# Synology Threat Prevention SRM parity report

The stock Cypress router package supplies ARM64 binaries for the inspection engine, daemon, and native WebAPI modules. Synology did not supply an x86-64 build of that backend for the target NAS. The port therefore uses an x86-64 Suricata engine and a Python/SQLite compatibility backend while reusing the stock screens and API names. This replacement is the starting point for the comparison. [Stock package inventory](ThreatPrevention-1.3.3-0926-package-review.md#3-how-the-spk-is-laid-out) · [Port architecture](backend-replaceability.md)

Inline IPS and per-device enforcement are parity gaps of the passive IDS architecture. Three defects affect the IDS itself. SQLite retention can erase the entire event history, a rule update can report success after a failed engine reload, and an address-scoped policy can affect traffic beyond the selected signature.

## Versions and evidence

- **DSM port:** repository HEAD `cdc5b9367cc59993c76121236726c675004162f4` plus the local Telegram, Ethernet, and map changes present on 2026-11-26. The package uses Suricata 8.0.6 and SQLite. [Build pin](../spk/common.sh#L29) · [Engine version](../VERSION) · [Repo architecture](backend-replaceability.md)
- **Stock router package:** Synology Cypress builds for the RT6600ax family. The repo pins [1.3.3-0926](https://global.download.synology.com/download/Package/spk/ThreatPrevention/1.3.3-0926/ThreatPrevention-cypress-1.3.3-0926.spk). I also inspected [1.3.4-0927](https://global.download.synology.com/download/Package/spk/ThreatPrevention/1.3.4-0927/ThreatPrevention-cypress-1.3.4-0927.spk). The two artifacts ship byte-identical `ui/synoips.js` and `webapi/SYNO.TPS.lib`. The manifest declares 21 APIs and 42 distinct API-method pairs, with Policy.delete declared at two versions. The newer build changes the native libraries, all eight WebAPI binaries, and the sensor restart hook, so matching API declarations establish the same visible contract and leave native runtime differences open. [Synology release notes](https://www.synology.com/en-global/releaseNote/ThreatPrevention?model=RT2600ac) · [Repo’s stock package inventory](ThreatPrevention-1.3.3-0926-package-review.md)
- **Verification:** compared shipped UI call sites, help, API metadata, and package scripts with the port. A cached Linux container ran the full compatibility suite and isolated fixtures for the backend defects marked **Reproduced**. **Code-confirmed** findings follow directly from the inspected paths. **Conditional** findings depend on the installation, traffic, or data. The review used no live router or NAS. As a result, packet enforcement, DSM UI behavior, real notification delivery, and vendor-specific database behavior remain outside the runtime evidence.

## Protection and operational integrity

| Impact | Feature | Stock SRM behavior | DSM port finding |
| --- | --- | --- | --- |
| Critical | Inline prevention and network security mode | Router-path IPS can drop high-risk packets. Availability and security modes control behavior in the inspection path. | **Missing by design.** Capture is passive AF_PACKET on a NAS interface or a mirrored traffic copy. `enable_prevention` is forced off and the selected mode is stored for UI compatibility. Neither default drop nor a Drop policy can block the original router traffic. [SRM settings](https://kb.synology.com/en-my/SRM/help/ThreatPrevention/threatprevention_settings?version=1_3) · [Port sensor](../spk/src/threatprevention/python/tpsweb.py#L294) · [Capture configuration](../spk/src/threatprevention/package/etc/suricata/suricata.yaml#L56) |
| Critical | Log retention at the configured quota | SRM rotates older history when the limit is reached. | **Broken, reproduced.** The loop deletes batches and uses the main SQLite file’s physical size as its exit condition. Deleted pages remain allocated until the final `VACUUM`, which runs after the loop. With a scaled 1 MiB quota and a real SQLite file, all 552 events disappeared across two batches. The quota also excludes the write-ahead log (WAL) and raw EVE logs. [Rotation algorithm](../spk/src/threatprevention/python/store.py#L327) · [Engine outputs](../spk/src/threatprevention/package/etc/suricata/suricata.yaml#L39) |
| High | Address-scoped exceptions | The stock policy editor ties source and destination constraints to a selected signature and action. | **Broken, reproduced.** The compiler preserves the original SID and appends a separate rule using only source/destination IP conditions. The new rule loses the original protocol, ports, flow and content conditions. A Pass or Disable policy can therefore suppress unrelated inspection for that address pair. An Alert policy can create unrelated events for the pair. The fixture verified generated rules. Packet-level effects remain untested. [Stock policy contract](api/official-app-surface.md#signatures--policy) · [Port compiler](../spk/src/threatprevention/python/compiler.py#L160) |
| High | Rule update, removal and live reload | Update Now and scheduled updates replace the active signature set and report their result. | **Broken, reproduced.** Reimports upsert rows and retain SIDs removed from the new catalog. The reload helper reports success after a nonzero process exit, and update and policy callers discard its result. The updater skips rule validation before writing the new file. The UI can report success while the running engine still uses an older ruleset. ## Capabilities represented in the port

The port has real EVE-backed event lists, detail and paging, SQLite policy storage, simple signature and class actions, trend and top-event calculations, rule feed configuration and scheduling, and SQLite log clearing. Those paths explain why the stock tabs can populate even when a workflow inside the tab diverges. Telegram, local host lookup, router traffic mirroring and Suricata acceleration settings are community additions.
